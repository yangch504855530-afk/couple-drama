# PM 评估:当前最大的问题 (2026-10-01)

- 方法:项目全量文档/代码/git 审查 + 3 路并行联网调研(竞品市场格局 / 国内分发渠道 / 情侣品类用户留存证据),每条结论标注证据强度
- 结论只代表评估时点状态;本文件是分析,不是迭代指令

---

## 一、最大问题(裁决):验证循环缺失 —— 产品运行在"开发者灵感 + AI 评审"的闭环里,真实用户数 = 0

**30+ 小时内迭代 11 个版本(v1.0→v3.0)、7 轮 AI 盲评(A-F/六画像/三体验官)、23 项单测、累计 40+ 项修复,但至今没有任何一个外部真实用户打开过这个产品;唯一触手可及的真实用户(妻子——产品的起源用户)的使用记录与原话反馈,从未出现在任何迭代文档中。** 盲评画像 A"新婚旅行情侣(爱拍照 vs 爱躺平)"就是她本人,但 7 轮评审都由 AI 代演了。

三条证据链支撑这个裁决:

1. **项目自己的结论被自己违反。** BUSINESS-RESEARCH.md(2026-09-30 商业化调研)最正确的一句话是"先攒 30 对真实情侣 30 天反馈再变现"——这是全部调研文档里唯一指向行动的战略结论,此后 6 个版本(v2.0→v3.0)的迭代全部与之无关。ROADMAP-v3 写的北极星"30 天后还在用的情侣比例,当前盲评预估 20-25%",其中"AI 盲评预估留存"是自相矛盾的修辞:北极星在 0 个真实用户时不可测量。
2. **边际收益已经归零。** 第 11 个版本的功能打磨对 PMF 的贡献趋近于零,而第 1 个真实用户的信息价值是无穷大。当前的每一轮 AI 盲评都在优化"AI 口味的完美",而 AI 口味与真实情侣口味的偏差,恰恰是这个品类所有死掉的产品犯过的错(见下)。
3. **品类坟场的共性死因正是"未验证就堆功能"。**【实证】中国独立情侣 App 几乎全灭:爱情银行(暴雷)、小恩爱(植物人式续命)、微爱/恋爱ing(事实沉寂)、QQ 情侣空间(大厂主动降级)、Between(国民级→2022 解散→2025 被当作非核心资产卖掉)。活着的只有:恋爱记(靠"打卡返现"类资金盘,争议缠身)、心动日常/Couple2(出海买量,25 人 5 年累计收入不到 100 万美元)。它们没有一家死于功能不够多。

## 二、验证缺失遮蔽着的其他重大问题(按严重度排序)

### P0(安全隐患,一旦有真实用户即事故)

- **全局共享一个硬编码 Gist,匿名可读。** `github-sync.js` 中 GIST_ID 硬编码,秘密 Gist"知道 URL 即可读",而 URL 在公开仓库的前端源码里 → 任何人可读**所有房间**的事件流/清单/夸夸/日志/需求状态。这与 AGENTS.md 自己的红线"情侣互动数据属高敏——最小化采集是底线"直接冲突。
- **"日志默认私密"裁决与实现矛盾。** VERDICT 裁决"日志感想默认私密",但 `syncState/collectLocal` 把 `cd.log` 全量明文推上公开可读的 Gist。按项目自己的裁决标准("胶囊明文上云=没封"),日志同理:明文上云=没封。这是 v1.1 盲评 E 抓过的"宣传与实现脱节"第三次出现(前两次:低迷过滤是假的/主权没强制;另:index.html 版本文案停留在 v2.2"同框递着用、进度存本机",而 js 已是 v3.0 全量同步)。
- 当前 0 用户所以暂无实害——但**先获客后补安全的顺序等于把事故排进日程**。

### P1(分发地基:即使推广,一半流量到不了)

-【实证】GitHub Pages 大陆间歇性屏蔽(GreatFire 判定 pages.github.io 被屏蔽;2025 年多起"时好时坏"实测记录)。【实证】微信内打开 github.io 弹"非微信官方网页"先导页,未备案域名可能直接被拦到"复制到浏览器"。
- 产品第一分享动作是"微信发链接给对方"——两个流失点叠加,**核心传播链路在一部分手机上直接失败**。修复成本≈0:腾讯 EdgeOne Pages 免费托管、免备案、国内可达。

### P1(价值链断裂:双人价值对目标用户不可达)

- v3.0 三大支柱(全量同步/回应卡/胶囊倒计时)全部依赖绑定+云同步,而云同步写权限需要用户自建 GitHub token 并粘贴【实证,代码】。目标用户(大学生情侣/普通夫妻)完成率趋近 0。不绑定则产品退化为单机抽卡玩具——"双人"是产品名里的第一个词。
- 竞品证据:品类第一流失原因是"一方拉着另一方"(从业者公开承认 common),本产品把第二重门槛(token)叠在第一重(双人激活)之上。

### P2(机制方向与品类证据相逆)

-【实证】品类反例判据:**台阶若由"义务/坚持"构成 → 崩盘**(恋爱记 1314 打卡→"今天你忘签明天我忘签,吵了一架人财两空";streak 学术研究=损失厌恶+社交压力);**台阶若由"好玩的内容"构成 → 成立**(双人成行 3000 万份、BYU 76% 正面数据)。
- v3.0 加重的时间胶囊、50 件清单、连击属于"坚持型"侧;抽卡小剧场/递台阶属于"好玩型"侧。方向上,最新迭代在向证据的反侧加码(虽然"休演不惩罚/免战牌"红线部分对冲了义务化,这是项目超出行业平均的自觉)。

### P2(定位漂移)

- v1.x 为自己夫妻(旅行矛盾)→ v2.0 校园版 → v2.3 通用 → 异地模式列未来第一优先。校园功能(恋爱天数/50 件校园小事)已是默认主体功能,但起源用户是自驾旅行的夫妻。给谁的问题没有被显式回答过。

### P3(形态天花板,非当前急务)

-【实证检索未果】情侣品类 15 年没有成功的持续型网页产品;中国的"网页形态"生态位由微信小程序占据。网页的冷启动优势(免下载即开即玩,品类最低激活成本)真实存在,但留存天花板低。中期若认真做,网页应定位为传播层,留存层考虑小程序。

## 三、客观说明:项目做对的事(不是客套,是资产)

- **反内卷红线(休演合法/免战牌/不追问)与品类实证的死因(义务化打卡)正面相抵**——这是真实差异化,不是口号。
- **单机同框是品类最优冷启动设计**:Andrew Chen 原子网络理论下,把激活从"2 人 2 机 2 次安装"压缩为"1 人 1 机 1 次打开"。
- **递台阶=修复尝试(Gottman repair attempt)产品化**,同类道歉场景有 WishCupid 付费验证;抽卡→即兴执行有抖音"情侣抽卡"内容验证的传播力。
- 工程纪律真实存在(修复必浏览器实证/schema 门禁/23 单测)——但注意:**以上全部是"设计与执行质量",没有一条是"需求验证"。产品死于需求假设的概率远大于死于设计质量。**

## 四、PM 建议的下一步(供决策,非指令)

1. **硬冻结功能开发**。第 12 个版本的边际价值 < 1 个真实用户的反馈。
2. **第 0 优先(零成本):n=1 验证闭环**——让妻子真实使用 7 天,记录打开频次、玩了几场、弃用了什么、原话是什么。这是全项目目前唯一没做过、且成本为零的验证。
3. **半天修地基**:迁移 EdgeOne Pages(国内+微信可达);index.html 文案与 v3.0 实现对齐;Gist 共享读问题在获客前必须有答案(哪怕先撤下"绑定"入口只留同框单机)。
4. **送 20 对真实情侣**:小红书情侣内容种草(优势赛道,体验型笔记,不贴外链)+ 校园表白墙/QQ 群(哄哄模拟器先例:情侣网页在学生 QQ 生态 24h 60 万用户)。绑定功能在门槛问题解决前不要作为推广点。
5. **预设止损决策点**:20 对中 30 天后仍在用 <3 对 → 停止"产品化",收敛为单场景工具(道歉台阶 / 情侣卡牌)或承认这是自娱项目。≥8 对 → 再谈 v3.1。
