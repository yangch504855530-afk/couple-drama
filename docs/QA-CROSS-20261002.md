## 一、总判决

**用户反馈属实:问题不是零星 bug,是一个架构级缺陷 + 三类系统性错误。** 三路独立测试指向同一个根因:

> **产品没有"当前持机人"概念。** 所有归属逻辑锚定在 UI 列位(`you`/`her`)和写死的字符串"你",而不是操作者身份。同框时换人接手,页面视角不变;异地时操作者身份被写死为创建时的快照。这是一个"单视角单人应用 + 双人数据槽位"的拼装,不是真正的双人应用。

三类系统性错误:
1. **身份/名字三轨分裂**:`cd.profile(you/her)`、`cd.binding(myName/partnerName)`、邀请码内嵌 name 三套真相互不同步——实测甲机导入对方码后绑定卡显示"**她 × 她**",同屏并存三套称呼。
2. **相对键跨机翻转**:事件 payload 里 `to:"you"`、`who:"you"` 是相对引用,两台设备上语义相反——夸夸被记在对方名下、免战牌额度两机各算各的(合计可打 8 张而非 4 张)、"TA 给你存了 N 句"报的其实是发给 TA 的。
3. **合并/同步层数据损毁**(node 实证):mergeFull 三处去重键错误——things 用 `[x.id,x.date]` 但数据是纯数字数组(键全塌缩成 `[null,null]`,**每次同步小事清单只剩 1 条**)、repair 无 id 字段(同天台阶只剩第一条)、log 键含可变 note(编辑感想后同场演出记两条,连击虚增);push() 读 Gist 失败时用空对象覆盖全云。
