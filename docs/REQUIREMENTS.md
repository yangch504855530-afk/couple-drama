# 《双人戏精》需求评审文档 (REQUIREMENTS)

- 版本: v1.0 ｜ 日期: 2026-09-30 ｜ 状态: 评审通过
- 产品定位: **独立**的模拟人生式双人小剧场游戏（与旅行攻略工具完全解耦，旅行只是可用场景之一）
- 目标用户: 喜好不同的情侣/夫妻——典型画像：一方爱"坐着发呆喝东西"，另一方爱"拍照跑动"；日常存在"互相有要求、互相达不到、互相被说"的微型摩擦
- 交付形态: 纯前端单文件 HTML（零依赖、离线、手机优先），独立仓库 + GitHub Pages

## 1. 背景与目标

真实痛点：旅行/日常中，两个人对"怎么玩"有不同期待，互相迁就变成互相要求。本产品把摩擦**游戏化**：矛盾变成戏码、要求变成抽卡、批评变成需求条体检。设计原则：**唯一验收标准是笑**。

## 2. 用户故事

| # | 作为… | 我想要… | 以便… |
|---|---|---|---|
| US-1 | 关系中的一方 | 每天打开就有现成的"今日主线/支线"，不用想今晚玩什么 | 零决策启动 |
| US-2 | 被拍照追着跑的一方 | 抽到结构化出片戏（不许互相指导/三脚架自拍） | 拍照不再是我的考核 |
| US-3 | 觉得自己付出没被看见的一方 | 用"需求条体检"告诉对方我告急了 | 用游戏语言代替抱怨 |
| US-4 | 想喊停的一方 | 打免战牌，本回合作废且不被追问 | 保住自己的节奏 |
| US-5 | 两个人 | 完成的戏码进"剧场日志"，坚持有连击和成就 | 把"经营关系"可视化 |

## 3. 功能需求与验收标准

- **FR-1 戏码卡库**: 8 花色 × 12 张 = 96 张（温柔🌅/整活🎭/出片📸/公路🚗/居家🍳/室内🌧️/消费💰/睡前🛌），每张含 title/text/minutes(5|15|30|60)/where(any|home|out|road)。支持按花色/时长/场景筛选；抽签不与当日已抽重复。
- **FR-2 每日剧场**: 按日期确定性生成主线（温柔戏）+支线（整活戏）；完成打勾；双方昵称可自定义。
- **FR-3 需求条**: 双方各 8 项（咖啡因/电量/出片欲/被投喂/被认可/驾驶余量/掌控感/惊喜感），点按循环 充足→偏低→告急；每项含"低值表现"与"充能动作"；告急弹提示。
- **FR-4 免战牌**: 每人每天 2 张，打出后本回合作废、对方不可追问；次日重置。
- **FR-5 角色轮换**: 8 角色（首席司机/摄影总监/干饭官/财务大臣/导航官/经纪人/战地记者/队医），各含职责+特权，点按分配给"你/她/待分配"。
- **FR-6 连击与成就**: 双方任意戏码完成记 1 分（当日去重）；连续完成天数=连击；成就 ≥10 枚（如 连击3/7/21、集齐一个花色、免战牌零使用周、累计 25/50/100 张）。
- **FR-7 剧场日志**: 已完成卡片按时间倒序展示，可附一句感想（≤50 字），本地保存。
- **FR-8 数据规则**: 全部存 localStorage（按日期键，跨天自动重置每日项）；清空数据入口；无任何网络请求。

## 4. 非功能需求

- NFR-1 单文件离线；NFR-2 手机 390px 零横向溢出；NFR-3 零依赖测试（Node assert）；NFR-4 确定性：同日期抽取结果全设备一致；NFR-5 免战/告急等敏感机制有防滥用文案（禁止翻旧账）。

## 5. 范围外

多人(>2)、账号/云同步、实体卡电商、非双人关系模式。

## 6. 验收流程（goal 模式盲评）

独立评估代理 ×3（新婚情侣 / 老夫妻 / 冷战修复期）+ 回归终验 ×1；每人持目标清单黑盒操作网页，PASS/FAIL+证据；修复后 D 轮复验。全部目标达成且无阻断缺陷 = 通过。
