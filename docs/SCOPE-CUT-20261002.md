# 功能瘦身裁决:砍什么、留什么、主线是什么 (2026-10-02)

- 背景:11 个版本迭代的功能堆积,用户反馈"太乱"。本文件给出全量功能裁决与新的信息架构
- 前置:DIRECTOR-PLAN-20261002.md(证据驱动)、PM-ASSESSMENT-20261001.md

---

## 一、乱的根源:三个产品塞在一个壳里

11 个版本不是把一个产品做厚了,而是把**三个不同的产品**焊在了一起:

| 隐含产品 | 包含功能 | 心智 |
|---|---|---|
| ① 双人小游戏 | 戏码卡/抽卡/演出/战报(起源功能) | "我们一起玩个乐子" |
| ② 关系沟通工具 | 需求条/今日需要/回应卡/状态机/加权抽卡/免检锁/需求体检/递台阶/免战牌 | "我们管理一下这段关系" |
| ③ 仪式感记录本 | 小事清单/时间胶囊/夸夸存折/关系气候/成就日志/连击节拍 | "我们记录和积累点什么" |

用户在同一屏里被要求切换三种心智——这就是乱的根源。品类证据(双人成行 vs 恋爱记)说明:①是成立的,②③里一半是毒药侧。代码证据:renderToday 250 行占 app.js 37%,6 个页签,3 套进度系统(连击/成就/气候),3 套记录系统(日志/存折/清单),2 套沟通系统(需求条/台阶)。

## 二、核心主线与核心分支(裁决结果)

```
                 ┌─────────────────────────────┐
                 │   主线:今晚演一场(唯一主界面)  │
                 │  打开 → 抽一张卡 → 演 → 笑    │
                 │  → 收尾:互相夸一句 → 战报截图  │
                 └──────────┬──────────────────┘
                            │ 只有两个次级入口
              ┌─────────────┴─────────────┐
        ┌─────┴─────┐              ┌──────┴──────┐
        │ 分支1:台阶  │              │ 分支2:百宝箱  │
        │ 吵架了才来, │              │ 想一起做点什么 │
        │ 2次点击递出 │              │ 时来翻:小事   │
        │ (低频急救)  │              │ 清单/时间胶囊/ │
        └───────────┘              │ 我们的记录     │
                                   └─────────────┘
```

- **主线 = 演一场**:这是产品的存在理由(唯一验收标准是笑)。同框、免登录、打开就玩。
- **分支 1 = 台阶**:低频但单场景价值最高(WishCupid 验证过的付费场景)。吵架时 2 次点击递出,平时不出现。
- **分支 2 = 百宝箱**:没事可做时来翻灵感(50 件小事/胶囊/过往记录),服务"仪式感"心智,全部收进二级页面。
- 三条线的公共规则(免战牌/休演/节拍)是**规则不是功能**:逻辑保留,收进设置与流程内部,不占 UI、不被感知。

## 三、逐项裁决(26 项功能盘查)

### 砍/下架(9 项)——同框模式下无存在意义,或品类实证毒药侧

| 功能 | 裁决 | 理由 |
|---|---|---|
| 需求条/今日需要 | **砍** | 同框时用嘴说就行;它的全部价值依赖异步绑定,而绑定已下架。义务型机制(每日自报),恋爱记式毒药侧 |
| 回应卡(三按钮) | **砍** | 完全依赖绑定+对方 needs 数据,同框下不存在 |
| 需求状态机(active/acked/fulfilled/skipped) | **砍** | 为需求条服务的复杂度,皮之不存 |
| 需求加权抽卡(35/55/80%) | **砍** | 依赖对方 active needs,同框下不存在;且"概率补偿"心智偏工具 |
| 今日免检锁/需求主权 | **砍** | 为需求条服务的规则 |
| 需求体检页签 | **砍** | 整页签随需求条下架 |
| 绑定/同步码/Gist 云同步 | **下架(代码保留)** | P0 安全+token 门槛;等决策门 1 证据后用 Workers+D1 正解 |
| 角色分配(8 角色) | **砍** | 角色已内嵌在每张卡里,独立分配系统冗余(A2 实测同住场景用不上) |
| 关系气候 | **砍** | 三套进度系统留一套;天气隐喻好,但与成就/连击功能重叠 |

### 并入主循环(3 项)——保留价值,消灭独立系统

| 功能 | 处置 |
|---|---|
| 夸夸存折 | 变成主线收尾动作:演完互相夸一句(5:1 实证价值保留),自动入存折;不再是独立页签系统 |
| 电量降载 | 保留逻辑:抽卡时可选"今晚累"→出轻场;一个按钮,不做成三档设置流程 |
| 免战牌 | 保留:演出中的按钮,规则写死在流程里 |

### 降级/藏(5 项)——功能在,存在感降级

| 功能 | 处置 |
|---|---|
| 成就(14 枚) | 页签砍掉,改为彩蛋式弹出("解锁:修桥人");不追求、不列表 |
| 连击/演出节拍 | 逻辑保留(休演缓冲已做好),节拍在设置里改;首屏不展示连击数字——反内卷红线下,连击不该被用户看见 |
| 时间胶囊 | 移入百宝箱二级入口。义务侧机制(写了要回来拆),但它是唯一自带回访理由的功能——验证期观察,不推广 |
| 日志/我们的记录 | 移入百宝箱,作为"回忆"翻阅 |
| SOS 急救条 | 就是分支 1 的入口本身,不再首屏常驻 |

### 保留为主干(4 项)

| 功能 | 角色 |
|---|---|
| 戏码卡池(96 卡)+每日抽取 | 主线燃料 |
| 演出流程(抽→演→收尾) | 主线本体 |
| 递台阶(3 预设+回执) | 分支 1 全部 |
| 小事清单(50 件) | 分支 2 主内容(小红书清单型已被验证 4.2 万收藏,也是内容营销素材库) |

### 新增(1 项,唯一豁免)

| 功能 | 角色 |
|---|---|
| 戏精战报分享图 | 演出收尾的可选动作:生成一张可存相册的图(今晚演了什么+最炸一句+产品名)。传播引擎,哄哄验证的"可截图可炫耀"机制 |

## 四、瘦身后的信息架构

- 页签:6 → **1 主界面 + 2 次级入口**(今日剧场 ｜ 🪜 ｜ 🎁)
- 首屏只有一个动作:抽卡。所有规则(免战/休演/节拍)内嵌不可见。
- 预计裁掉的代码量:需求一族+绑定一族+体检页签 ≈ app.js 1/3、binding.js 331 行、github-sync.js 183 行、capsules 元数据同步——**产品回归 73KB 单文件、零依赖、打开即玩的初衷**。
- 96 张卡、3 台阶、50 件小事、14 成就等内容资产全部保留——内容是这个产品最值钱的部分,系统不是。

## 五、执行原则

1. 砍功能是"UI 下架+代码保留"(feature flag 式),不做破坏性删除——决策门 1 后若走 C 路径(记录实体化),需求/记录一族可能复活。
2. 瘦身与阶段 0 地基(EdgeOne 迁移/统计下架/文案对齐)合并为**一次发布**完成,避免多次折腾。
3. 瘦身后跑一轮 AI 盲评回归(单机同框主流程)+ n=1(嫂子 7 天),再开始推广。
