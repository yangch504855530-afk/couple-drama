# v3.0「我们的故事」产品规划 (ROADMAP-v3)

- 日期: 2026-10-01 ｜ 作者: PM ｜ 状态: 待用户体验官评审
- 北极星: **30 天后还在用的情侣比例**（当前盲评预估 20-25% → 目标 50%+）
- 核心洞察（来自六轮盲评+需求调研）: 留存的天花板不取决于功能数量，取决于**产品里有没有"删不掉的东西"**——数据资产才有留存，玩具只有生命周期。

---

## 一、根因诊断（为什么当前留不住）

| 根因 | 证据 | 对策 |
|---|---|---|
| 内容是存量不是增量 | 96 张卡三周抽熟 | 剧情卡：内容改由关系本身生成（照片说明/原话/反应） |
| 互动无闭环 | 想你了只存本机，对方看不到 | **全量云同步**：一切动作自动到达对方 |
| 无"非打开不可"时刻 | 所有功能皆可选 | 时间胶囊：写了就有一个"到期必回"的约定 |
| 数据无重量 | 删除无成本 | 回忆资产化：积累的日志/夸夸/小事成为不可复制的唯一副本 |

## 二、三大新支柱

### 支柱 1：全量云同步（根因 3 修复）

不再只同步三样核心，**双方的一切数据自动互通**：

- 同步内容：今日需要、想你了、递台阶+回执、小事清单、夸夸存折、剧本记录、日志感想（可选公开）、时间胶囊
- 机制：事件流全量上 Gist 云端，双端自动拉取合并（30 秒轮询+打开即拉）
- 冲突策略：各自字段各写各的（自报原则），冲突时 newest-wins
- 解绑：任一方发起 → 对方确认 → 云端 30 天后清空，本地自选"删除/留作纪念"
- **前提**：需绑定（同步码或 GitHub token 云同步，均已就绪）

### 支柱 2：剧情卡（日志升级为"我们的编年史"）

每场演出、每次回应、每个台阶的记录，从"一行字"升级为**可沉淀的剧情条目**：

- 字段：日期 + 事件 + **一句话记录**（已有 note 字段强化）+ **心情标记**（😀/😍/😔/😮）
- 时间线视图：按日期排列的"你们的故事"，支持翻阅
- 导出：一键复制全部文字（未来实体纪念册的原料管道）

### 支柱 3：时间胶囊（延迟满足 = 天然回访锚点）

- 写一段话给对方（或给自己），**设定解锁日期**（1 周/1 月/3 月/1 年）
- 锁定期间：双方都看到"🔒 有一封 X 天后可拆的信"（期待感）
- 到期：打开页面看到"🔓 有信可拆"，拆信展示全文
- 这是唯一合法的"隔很久也要回来"机制——不靠催，靠惦记

## 三、既有功能在新架构下的位置

| 功能 | 处置 |
|---|---|
| 节奏主权/休演/电量 | 原样保留（反内卷底线） |
| 递台阶/今日需要/想你了 | 保留 + 云同步自动传达 |
| 96 张卡池 | 保留；加权抽卡保留 |
| 需求体检/免检 | 保留；状态仅本人标、免检不可见（主权原则不变） |
| 50 件小事 | 保留；校园版后续加职场版切换（v3.1 候选） |
| 角色分配 | **降级**：收进"更多"折叠（A2 反馈"同住场景用不上"） |
| 成就墙 | 保留；文案去 KPI 化已在 v2.2.2 完成 |

## 四、明确不做

订阅/广告/打卡返现/推送通知/定位监控/社交广场/照片上云（隐私+体积）。

## 五、里程碑

- M1：全量同步引擎 + 绑定卡重构（云同步作为默认路径）
- M2：剧情卡 + 时间胶囊
- M3：时间线视图 + 导出
- 评审：用户体验官 ×3 评价规划 → 修正 → 实现 → 部署

## 六、请用户体验官重点评审的问题

1. 全量同步后，"删不掉的东西"是否真的能提升 30 天留存？还是反而增加"分手删数据"的心理负担？
2. 时间胶囊的解锁日期机制：会不会写了就忘（到期不回来）？什么解锁周期最合理？
3. 剧情卡的"一句话+心情"粒度是否够？会不会因为要写而变成新负担？
4. 这份规划里，哪个功能你应该砍掉（看起来有用实际不会用）？
